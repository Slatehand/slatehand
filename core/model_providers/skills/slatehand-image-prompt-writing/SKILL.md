# 全局生图提示词写作

适用于项目关键帧、其他图片、地点普通图与全景图，以及 Playground 中所有支持图片输入的生图或改图能力。本 Skill 是强制写作规范，插件专用 Skill 只补充标签、画幅与模型写法，不取消本规范的引用说明与正文对应要求。角色设定图由 Core 编译，不由 Agent 改写。

## 写作前确认实际输入

1. 读取当前插件约定与实际提交清单：关键帧看 `image_inputs` 的 `asset_id`、`label`、`roles`；地点图按 `reference_asset_ids` 顺序；其他图片合并计算角色造型与显式辅助参考。编辑底图固定排首位，同一 Asset 合并用途不重复编号。
2. 有参考图时必须用自身多模态能力实际看图（项目用 `read_media_input`，Playground 看可见图片）。文件名、历史提示词、角色名与计划文字不能代替看图。
3. 无法看图时明确告知用户，请用户提供各标签图片内容、用途与保留边界；说明充分时据此编写并注明来源，缺必要信息时暂停编写与生成，不猜测或擅改无图生成。
4. 标签严格按工作集 `image_prompt` 约定（默认 `<Picture1>`、`<Picture2>`；部分插件多图用 `<image1>`、单图用“图片”）。不虚构未提交输入，参考增减或重排后重新核对标签。
5. 服从用户指定语言；未指定时按当前插件专用写法，标签保持插件原样。

## 有参考图：引用说明 + 画面正文

新写或修改提示词时，必须将以下两部分完整保存到 `prompt_text`：

- 开头按实际输入顺序每图一行：`标签: 用途与保留边界`（不写文件名、路径或 Asset ID）。
- 空一行后写画面正文（可带“画面正文：”标题），明确引用每个实际标签说明保留什么、调整什么，不能只在开头列标签而正文笼统写“参考图/场景不变”。
- 将身份、造型、画风、空间、材质、光线、姿态、构图正交剥离（写清“只取什么；不采用什么”）。只继承指定属性：群像设定图须显式剥离本帧不在场的其他人物（如孩童、随从）、浅灰底与尚未发生的伤妆血迹；地点图须剥离本帧尚未发生的状态（如未起火时的火光浓烟）与全景畸变，不把“仅参考画风”扩成照搬人物，不把场景参考变成固定机位。
- 场景参考按本图画框决定继承什么：画框内可见结构才保留；近景、特写通常只取光线、色温和材质。不要笼统写“以某张图为场景基础”：模型会连同参考图的景别和构图一起搬过来，把近景拉远。
- 变更构图时交代新视角、透视、遮挡与新露出区域；已有身份图时只写本帧表情、姿态和位置，不重复描写五官服装。
- 只写静态画面，不用运动过程代替空间布局；画幅句由 Core 或插件编译，正文不重复写画幅。

Core 只核对显式标签数量、顺序与正文引用，不自动拼接默认用途或补写引用说明。

### 多图示例（默认标签）

```text
<Picture1>: 画风参考。采用线条、色彩、材质表现与光影风格，不沿用其中的人物、场景和构图。
<Picture2>: 场景参考。保留建筑结构、固定陈设及其空间关系，机位、景别与主体姿态以正文为准。

画面正文：
采用<Picture1>的线条、色彩、材质表现与光影风格。
画面中可见的控制台、主座、立柱与拱窗保持<Picture2>中的建筑结构与相对位置。
将摄影机移至控制台内侧，朝向主座，采用平视中近景；控制台边缘位于前景，主座位于画面中央，
背景保留可辨识的立柱与拱窗。根据新机位重新组织透视与遮挡关系，不照搬<Picture2>的原始构图。
```

### 近景示例（场景参考只取光线与材质）

```text
<Picture1>: 身份与造型参考。保留五官、发型和服装，姿态与构图以正文为准。
<Picture2>: 光线与材质参考。只取冷色窗光的色温和被褥的布料质感，不沿用其中的空间、门窗和构图。

画面正文：
保留<Picture1>中人物的身份与造型。俯拍近景，人物平躺，后脑陷入枕面，被褥压在胸前形成褶皱。
冷色窗光的色温和布料质感取自<Picture2>，光线斜切过一侧脸颊。背景只有床头板局部，浅景深虚化。
```

### 单图示例（单图用自然指代的插件）

```text
图片: 身份与造型参考。保留主体外观、服装和配饰，姿态与构图以正文为准，不复制参考图背景。

画面正文：
保留图片中主体的身份与造型，将其置于主座中央端坐，双手在胸前抱住书籍，目光朝向镜头。
采用平视中近景，背景依照已批准的场景描述建立，按新构图组织主体与背景的遮挡关系。
```

## 无参考图：只写画面正文

没有任何实际图片输入时，不写引用段、标签或“参考某图”，直接按已批准事实写媒介风格、主体静态姿态、空间层次、材质与光线，不新增未授权角色、道具或剧情。

## 生成前自检

- 有图时是否已亲自看图（或获用户充分说明并注明来源），每个实际标签是否按当前顺序同时出现在引用段与正文且不含文件名？
- 场景与人物参考是否按本图画框正交剥离，没有把近景拉远或带入不在场人物？
- 无图时是否直接写正文，未虚构输入标签？
- 工作集返回 `prompt_problems` 软提示时，是否已按提示消除了标签错漏、过长堆砌或括号否定补丁？
- 是否保留用户指定的语言和领域约束，没有重复画幅句或偷偷改写上游导演设计？只生成明确授权目标。
