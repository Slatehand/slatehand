# 连续关键帧生产

本 Skill 是关键帧计划落地成图的执行循环：**打样 → 排序 → 生成 → 看图审核 → 选择或重试 → 推进**。画面设计、帧数选择与正文规范仍以 `slatehand-keyframe-planner`、其 `references/` 与全局 `slatehand-image-prompt-writing` 为准。

目标是产出一组跨 Segment 角色、空间、道具、光线一致且可直接送入视频生成的静态关键帧（由你自查保证，人类审核兜底，Core 不据此拒绝操作）。

## 授权与范围

- 只在用户明确要求生成时执行，严格限于用户指定范围，不自动扩到其它 Scene 或顺带生成视频等媒体。
- 范围内推进无需逐帧向用户确认：先按第 1 节打样，再用 `media_batch(kind="keyframe", action="start")` 以显式 Keyframe 集合启动，每轮只提交依赖已满足的帧；本轮审核选定后用 `action="continue"` 带原批次 ID 推进下一轮。用户要求“生成完/按顺序全部生成”即视为授权继续批次；只要求一轮或某几张时完成后停下汇报。
- 计划未建立或需改镜头设计、共享边界时，先按 planner 规划，不在本循环暗改脚本或计划结构。你的选图人类随时可改选。

## 1. 排序：先打样，再按依赖，不按时间线

开始前一次性读取范围内全部 Segment 的关键帧计划（`read_story(level="segment", extensions=["keyframe"])`）与 `referenceable_keyframes`，并用 `read_media_input` 一次性看完本范围涉及的角色造型图与地点参考图（未变化不重复读取），理清依赖后再定顺序。

- **先打样，再铺开**：第一轮只用 `generate_media(kind="keyframe")` 提交首 Scene 锚点帧，必要时加 1 张景别或难点明显不同的帧（最多 2 张）。看图审核选定后排查其余计划是否有同类“计划错误”，修完再开批次；基调拿不准时先请用户看打样帧。切勿把整批直接交给 `media_batch`：被参考帧选定前无法写参考关系，刚规划完的帧彼此无依赖，一次 `start` 会全部提交，问题要等全跑完才暴露。
- **锚点帧**：每个 Scene 从已规划帧里选信息最全的一张作锚点（常为建立镜头或双人主镜，未必在时间线最前），先生成选定以锁定光线方向、造型与可见空间。全为近景时选最能定光与造型的近景，不为了当锚点把某帧拉远，也不加计划外全景。
- **星形参考，不做链式参考**：下游帧用 `reference_keyframe_ids` 参考锚点帧（必要时加前一帧），不做 A→B→C→D 链式参考以免累积漂移。身份以角色造型图为准，空间光线以锚点帧为准；不继承锚点景别构图，全景锚点不能拉远下游近景。
- 被参考帧选定后，才用 `edit_keyframes` 的 `update_frame_fields` 写入下游 `reference_keyframe_ids`。输入上限与造型图、前置帧、地点图共享（最多 5 张），只放必要参考。
- 打样通过后，所有依赖已就绪且互不参考的帧与 Segment“其他图片”应在同一轮并发提交并集中 `wait`，不要逐张串行生成等待。

## 2. 单个 Segment 的首尾帧

帧数服从最少必要原则。确需双帧时：

- **先首帧，再尾帧**：Core 把同段首帧作为尾帧改图底图。必须先看图审核并**选定**首帧再生成尾帧，否则 Core 会退用最新未选候选作底图。
- 同机位仅状态变化时，尾帧正文只写变化增量；机位或景别变化时，尾帧须显式要求按新机位重排构图、透视与遮挡，只保留身份、服装、道具状态与光线。
- 尾帧出图后与首帧并排比对发丝、服装褶皱、陈设与光影；补间会放大细微差异。重做仍对不上时用 `edit_keyframes` 的 `set_activation` 关闭一端退回单帧并说明。

相邻 Segment 连续、后段已启用首帧且无共享边界时，首帧优先从上一段已选视频抽取交接画面。`extraction_suggested=true` 的帧等待上一段视频选定后再抽取，批量生成会自动跳过它们；漏标时用 `update_frame_fields.fields.extraction_suggested=true` 补标。

抽帧流程：先 `read_details(kind="keyframe", ids=[...])` 看 `start_frame_extraction`。`state="ready"` 时调 `generate_media(kind="frame_extraction", target_id=<首帧 Keyframe ID>)`（默认抽倒数第 5 帧，可传 `frame_index`）；`waiting_source_video` 时请用户先选定上一段视频；`shared_boundary` 不抽帧。`wait` 后在 `list_candidates(kind="keyframe_image")` 看图审核并用 `select_keyframe_candidate(source="generation")` 选入；用户明确要求直接生成时才单独生成。抽帧须同步做到：
- **挑帧**：确保无运动模糊且处于本段启动前，否则用 `frame_index` 往前挑并说明重叠代价；
- **对齐正文**：先 `save_keyframe_prompt` 对齐该帧实际画面再选图（改正文会清选图）；
- **重写视频提示词开头**：只写该帧之后的动作；
- **上一段改选视频后重抽**：已选首帧不会自动更新。

同 Shot 因 `model_constraint` 拆段且机位不变时，不抽帧则设 `reuse_keyframe_id` 复用同 Shot 已选图：批次会跳过并等来源选定后变为 `reuse_ready`，再按第 3 节选入。

## 3. 复用已选关键帧

画面与人物状态不变的回切镜头及同 Shot 拆段延续帧，直接复用已选图：`select_keyframe_candidate(keyframe_id=<目标帧>, source="keyframe", source_id=<来源帧>)`。

- 复用是一次性选择同一 Asset，来源改选后需同步时再选一次；复用不产生共享边界接缝融合。
- 对白之间的细微表演由视频完成，只有静帧必须体现姿态、道具或光线变化时才改为参考重生成。
- 复用或用 `source="asset"` 选入项目图前，均须看图并核对目标帧正文与画面一致。

## 4. 看图审核

每条候选成功后用 `list_candidates(kind="keyframe_image", target_ids=[...])` 取 Asset ID，再用 `read_media_input` 亲自看图；无法看图时停止审核并如实告知。对照造型图、锚点帧、前置帧与参考帧逐项核查：

| 类别 | 检查点 |
| --- | --- |
| 动作状态 | 首帧是本段动作启动前、尾帧是已结束，进行中的画面不在首尾槽位；连续镜头的首帧来自共享边界或抽帧 |
| 景别与重心 | 第一视觉重心清楚够大，未被多余空间陈设稀释，也未被参考图构图拉远 |
| 身份 | 脸型、发型、年龄感与造型图一致；无多出、缺少或互换角色 |
| 造型 | 服装、配饰、伤痕、脏污与所选造型和剧情时刻一致 |
| 空间 | 陈设与朝向同锚点帧一致；站位、轴线、视线与前后帧可剪接 |
| 道具 | 持握左右手、开合损坏状态、数量与前后帧一致 |
| 光线 | 光源方向、时段、色温与锚点帧及 Scene 状态一致 |
| 情绪 | 面部与肢体准确传达当拍情绪，不过火或不足 |
| 结构 | 肢体关节、透视、接触受力自然，无悬浮穿插；无计划外文字水印，画内文字准确 |
| 视频适配 | 无运动模糊；画内说话者露脸且嘴部自然；安全区内主体完整 |

缩放可能导致手指等细小处看不清，只确认看清的部分，看不清如实说明，不写“已确认无瑕疵”。

## 5. 诊断与重试

不合格时先归因，不要盲目重写提示词：

| 原因 | 特征 | 处理 |
| --- | --- | --- |
| 随机瑕疵 | 提示词和输入都对，偶发手脸细节坏了 | 原样再调 `generate_media(kind="keyframe")` 换新 seed；`retry` 只用于失败、取消或不确定任务 |
| 提示词歧义 | 反复误读站位、左右手或情绪强度 | 只改歧义句再生成，不整段推翻 |
| 输入冲突 | 参考图矛盾或过多稀释身份空间 | 删减参考，每张图只留单一职责 |
| 能力上限 | 改写重试仍做不出该构图动作 | 停止并给替代构图或交人工修图 |
| 状态错位 | 首帧画成中途或结果、尾帧未演完、连续镜独立生图 | 按 planner 开头三问重新判断端点是否必要，进行中的画面优先用作其他图片。仍需定帧时按真实起止状态选择画面和来源 |
| 计划错误 | 多帧共犯景别过远、结果提前或照搬参考构图 | 停止提交，统一修完所有受影响帧（含未生成帧）再继续；涉脚本构图时按 planner 写回 |

- **禁止叠否定补丁治标**：候选图出现肢体或马匹畸变、结构粘连、群像杂乱时，绝不在原提示词里追加“严禁缺失”“绝无扭曲”之类的括号解剖禁令——根因往往是单帧塞入过多前景主体、无依据切超广角或姿态落在动作中途。应退回动作启动前的静止站姿、把次要人群推入远景虚化并精简正文；同时先消除工作集 `prompt_problems` 中的格式软提示。
- **重试预算**：每帧最多 3 次生成（含首次），同轮有可用候选即选最优，超预算停下带诊断问用户。
- `save_keyframe_prompt` 或 `edit_keyframes` 会**清除当前选中图**并阻塞下游引用帧；已选定帧无明确问题不改，所有正文修改必须落库保存。

## 6. 选择、隐藏与推进

- 审核通过立即 `select_keyframe_candidate(source="generation", source_id=<generation_id>)`，本轮全选完再 `continue`。
- 确认弃用的候选用 `manage_generation(action="dismiss")` 批量隐藏（Asset 仍保留）：
  - 只隐藏有明确依据的：看得清的结构缺陷、身份造型错误、违背镜头设计或计划已改；仅次优或拿不准的不隐藏。
  - 用完预算仍无合格候选时，留下最接近的一条让人看到问题。
  - 如实记录隐藏原因；重规划锁定 Segment 前须先隐藏未采用候选。
- 改选已被下游参考或复用的上游帧前，先列出受影响下游帧询问用户是否重做，不悄悄只改上游。
- 范围内的 Segment“其他图片”按同样依赖顺序生成、看图审核并用 `select_reference_image` 选入。

## 7. 停止条件与汇报

用完重试预算、需用户做创作取舍、缺未授权上游依赖或无法看图时停止推进。结束或停下时简短汇报：每帧所选候选、复用来源、各帧重试次数与原因、隐藏了哪些候选及原因、已知瑕疵与未核验部分。长任务结束、失败或需用户决定时，结束回复前调用 `ring_alarm`。
