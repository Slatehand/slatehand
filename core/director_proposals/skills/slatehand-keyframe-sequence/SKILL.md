# 连续关键帧生产

本 Skill 是关键帧计划落地成图的执行循环：**打样 → 排序 → 生成 → 看图审核 → 选择或重试 → 推进**。
画面怎么设计、帧数怎么选、正文怎么写，仍以 `slatehand-keyframe-planner`、其 `references/` 与全局
`slatehand-image-prompt-writing` 为准；本 Skill 不重复、也不改写那些规则。

目标是一组**连贯一致**的关键帧：同一角色、空间、道具与光线跨 Segment 保持一致，情绪与动作沿脚本连续，
并且每张帧都适合作为视频生成的输入。这些都是创作质量要求，由你按本 Skill 尽力保证，最终由人审核兜底；
Core 不据此拒绝任何操作。

## 授权与范围

- 只在用户明确要求生成时执行。用户给出的范围（例如“把 Scene 3 的关键帧按顺序生成完”）就是本次授权范围，
  不自动扩大到其它 Scene，也不顺带生成视频或其它媒体。
- 范围内的推进不需要用户逐帧确认：先按第 1 节打样，再用 `media_batch(kind="keyframe", action="start")` 以显式 Keyframe 集合启动，
  每轮只提交依赖已满足的帧；审核并选好本轮结果后用 `action="continue"` 带原批次 ID 推进下一轮。
  用户要求的是完整范围（“生成完”“按顺序全部生成”）时，这本身就是继续批次的明确要求；用户只要求一轮或
  只要求某几张帧时，完成后停下汇报，不自行 continue。
- 计划尚未建立、需要改写镜头设计或共享边界时，先按 planner 规划，不在本循环里暗改脚本或计划结构。
- 你的选择是可改选的工作结果，不是审核结论，人类随时可以改选。

## 1. 排序：先打样，再按依赖，不按时间线

开始前读取范围内全部 Segment 的关键帧计划（`read_story(level="segment", extensions=["keyframe"])`）和
`referenceable_keyframes`，画出依赖关系，再决定顺序。

- **先打样，再铺开**：第一轮只用 `generate_media(kind="keyframe")` 提交第一个 Scene 的锚点帧，必要时加一张景别或难点明显不同的帧
  （例如手部特写），最多 2 张。看图审核并选定后，检查问题是否也存在于其余计划（第 5 节“计划错误”），改完再启动批次；
  看不准基调（景别、风格、情绪方向）时先把打样帧给用户看。不要把整个范围直接交给 `media_batch`：参考关系要等被参考帧选定才能写入，
  刚规划完的帧彼此没有依赖，一次 `start` 会全部提交，问题要等全部生成后才暴露。
- **锚点帧**：每个 Scene 从已规划的帧里选一张信息最全的作为锚点，有建立镜头或双人全景时通常用它。
  它承载该 Scene 的光线方向、人物造型和它能看到的空间事实，最先生成和选定。锚点不一定在时间线最前面：
  多轮对话应先出双人主镜头，再派生过肩和特写，哪怕主镜头排在后面。Scene 全是近景时，选最能确定光线和人物造型的近景，
  不为了当锚点把某帧拉远，也不另加一张计划外的全景。
- **星形参考，不做链式参考**：后续帧通过 `reference_keyframe_ids` 参考锚点帧（必要时再加前一帧），
  不能只参考紧邻的上一帧。A→B→C→D 逐帧链式参考会把每一步的偏差累积下去，到后面人物和空间就漂了。
  身份始终以角色造型图为准，空间与光线以锚点帧为准。参考时不继承锚点的景别和构图，全景锚点不能把下游的近景拉远。
- 参考关系是计划的一部分：被参考帧选定之后，才能用 `edit_keyframes` 的 `update_frame_fields` 把它写进下游帧的
  `reference_keyframe_ids`。名额与角色造型图、前置帧、地点图片共享，合计最多 5 张，
  只放真正提供必要信息的图。
- 打样通过后，互不依赖的帧（不同 Scene、彼此不参考的 Segment）可以在同一轮里提交，不必全部串行。

## 2. 单个 Segment 的首尾帧

帧数遵守最少必要原则：能用单首帧或单尾帧表达的不启用双帧（判断方法见 planner 的“首尾槽位与最少约束”）。
确实需要双帧时：

- **先首帧，再尾帧**。Core 让同段尾帧以首帧为前置帧，并把首帧图作为改图底图提交。首帧必须先审核并
  **选定**，再生成尾帧；否则 Core 会退而使用首帧最新一条未选候选作为底图，尾帧就可能建立在被你拒绝的画面上。
- 机位与景别不变、只是状态变化时，底图让人物、空间和光线自然延续，尾帧正文只写变化部分。
- 机位或景别变化时，尾帧正文必须显式要求按新机位重新组织构图、透视与遮挡，只保留身份、服装、道具状态和光线，
  否则模型会照搬首帧构图。
- 尾帧生成后把两张图放在一起比较：发丝、皮肤、服装褶皱、陈设和光影是否对得上。视频模型要在两张图之间补间，
  细微差异会在中段变成融化或形变。对不上时重新生成尾帧；仍对不上就用 `edit_keyframes` 的 `set_activation`
  关闭其中一端退回单帧，并在汇报中说明。

相邻 Segment 连续（同一 Shot 拆段，或动作跨段未完）且没有共享边界时（上一段不启用尾帧），后段首帧优先用上一段视频的真实末帧：
提交批次前把这类首帧告诉用户，等上一段视频选定后再抽帧，不要抢先独立生图。工作集中 `extraction_suggested=true` 的帧就是人类或规划已标记的这类帧：
批量生成会自动跳过它们，不要改用单帧生成绕过；还没有标记时用 `edit_keyframes` 的
`update_frame_fields.fields.extraction_suggested=true` 补上。

抽帧由你执行：用户要求生产或继续这些关键帧时，先用 `read_details(kind="keyframe", ids=[...])` 查看该帧的
`start_frame_extraction`，`state="ready"` 表示上一段已采用视频，此时调用
`generate_media(kind="frame_extraction", target_id=<首帧 Keyframe ID>)`。默认抽倒数第 5 帧；需要别的时刻时给
`frame_index`（范围 `0…N-1`，越界时错误信息给出可选范围）。`waiting_source_video` 表示
上一段还没有采用视频，告诉用户需要先选定上一段视频；`shared_boundary` 表示该首帧与上一段尾帧共享，不抽帧。
用 `manage_generation(action="wait")` 等抽帧完成，再用 `list_candidates(kind="keyframe_image")` 找到登记到该帧的
抽帧候选，照常看图审核，合适时用 `select_keyframe_candidate(source="generation")` 选入；用户明确要求直接生成时才单独生成。

抽帧时还要：

- **挑帧**：这一帧必须是本段启动前、主体清楚、无运动模糊；默认帧不合适就用 `frame_index` 往前挑，并告诉用户离结尾越远，拼接处重复的动作越多。
- **对齐正文**：先用 `save_keyframe_prompt` 把首帧正文改成这一帧的实际画面，再选图，因为改正文会清除选中图。
- **重写视频提示词开头**：只写这一帧之后的动作，不重演已完成的部分。
- **上一段改选视频后重抽**：旧帧不再是上一段的真实画面，已选首帧不会自动更新。

同一 Shot 因 `model_constraint` 拆段、机位不变时，后段首帧不抽帧就复用同 Shot 已选图，不要独立生图：
`reuse_keyframe_id` 已设置的帧，批量生成跳过并等待来源选定（观测状态 `dependency_blocked`，
`dependency_kind="reuse_keyframe"`），来源选定后变为 `reuse_ready`，此时按第 3 节选入来源的已选图。
计划里漏设时，开始批次前用 `update_frame_fields.fields.reuse_keyframe_id` 补上。

## 3. 复用已选关键帧

画面与人物状态都没有变化的回切镜头（例如多轮对话里反复回到同一个特写），以及同一 Shot 拆段的延续帧，
直接复用已选图，不重新生成：

```text
select_keyframe_candidate(keyframe_id=<目标帧>, source="keyframe", source_id=<来源帧>)
```

- 复用的是**同一个 Asset 的一次性选择**，不建立活依赖：来源帧之后改选，目标帧不会跟着变；需要同步时再选一次。
- 复用不等于共享边界。只有相邻 Segment 显式共享同一个 Keyframe 才会在成片中做接缝融合；
  复用只是两张帧恰好选了同一张图。
- 只有脚本要求的表情、视线、姿态、道具或光线变化必须在静帧里成立时，才改为参考该帧重新生成；
  同一镜头里对白之间的细微表演由视频完成，不构成不复用的理由。
- 复用前确认目标帧正文描述的就是这张图的画面；正文与选中图不符会误导后续视频提示词与审核。
- 任一项目图片也可用 `source="asset"` 选入，例如用户导入的修图结果；选前同样要看图核对。

## 4. 看图审核

每条候选成功后都必须亲自看图。用 `list_candidates(kind="keyframe_image", target_ids=[...])` 取得产物 Asset ID，
再用 `read_media_input` 查看。没有视觉能力、工具没有返回可见图片时，停止审核并告诉用户，不能根据提示词或文件名
推断画面，也不能声称已核验。

审核要**对照参考图**，不能只对照提示词：把候选与所选角色造型图、锚点帧、前置帧和参考关键帧一起看。
逐项检查：

| 类别 | 检查点 |
| --- | --- |
| 动作状态 | 首帧是本段动作启动前、尾帧是已结束，进行中的画面不在首尾槽位；连续镜头的首帧来自共享边界或抽帧 |
| 景别与重心 | 第一视觉重心是否够大、够清楚，有没有被多余的空间和陈设稀释；实际景别有没有被参考图的构图带偏 |
| 身份 | 脸型、发型、年龄感与造型图一致；没有多出、缺少或互换的角色 |
| 造型 | 服装、配饰、伤痕、脏污等状态与本帧所选造型和剧情时刻一致 |
| 空间 | 陈设位置、空间朝向与锚点帧一致；人物站位与轴线、屏幕方向、视线方向和前后帧可剪接 |
| 道具 | 道具在哪只手、开合与损坏状态、数量与前后帧一致 |
| 光线 | 光源方向、时段、色温与锚点帧和 Scene 状态一致 |
| 情绪 | 面部、肢体与人物关系是否传达了这一拍的情绪，强度是否过头或不足 |
| 结构 | 手指、肢体数量与关节、透视、物体悬浮或穿插；人物与床、地面、手中物的接触是否有真实受力；计划外的文字和水印，计划内的文字是否写对 |
| 视频适配 | 没有运动模糊；画面内说话的角色脸部可见、嘴部自然；画幅安全区内主体完整 |

看图能力有上限：返回的图片若经过缩放，手指等细小瑕疵可能看不清，自家模型也容易对自己生成的问题视而不见。
审核结论只覆盖你实际看清的部分，看不清的部分如实说明，不写“已确认无瑕疵”。

## 5. 诊断与重试

不合格时先判断原因，再选择对应的处理，不要一律重写提示词：

| 原因 | 特征 | 处理 |
| --- | --- | --- |
| 随机瑕疵 | 提示词和输入都对，只是这一次手、脸或细节坏了 | 原样再次 `generate_media(kind="keyframe")`，Core 为每次提交分配新 seed；`manage_generation(action="retry")` 只用于失败、取消或提交不确定的任务 |
| 提示词歧义 | 多次出现同一种误读：站位反了、道具错手、情绪过头 | 小幅修改正文中产生歧义的那一句，再生成；不要整段重写 |
| 输入冲突 | 参考图之间互相矛盾，或参考太多导致身份或空间被稀释 | 删减或更换参考，使每张输入只承担一个明确职责 |
| 能力上限 | 改写和重试都无法得到某个构图或动作 | 停止，向用户说明，并给出可行的替代构图或交给人工修图 |
| 状态错位 | 首帧画成动作中途或结果，尾帧动作还没完成，或连续镜头独立生图 | 不重试、不改措辞：按 planner 开头三问换位置或换来源，必要时退回启动前重画 |
| 计划错误 | 同一类问题出现在多帧：景别都过远、结果都提前、都照搬了参考图的构图 | 停止提交，先修改所有受影响的帧（包括尚未生成的）再继续，不逐帧重试；问题来自脚本构图时按 planner“定位与上游”调整并写回 |

- **重试预算**：每帧最多 3 次生成（含首次）。用完仍不合格时停止该帧，带着诊断问用户，不无限循环消耗算力。
  同一轮中有多条可用候选时，选最好的一条即可，不为追求完美继续重试。
- 修改正文用 `save_keyframe_prompt`，修改参考用 `edit_keyframes`。改正文或参考会**清除该帧当前的选中图**，
  并让引用它的下游帧在它重新选定前无法生成；已选定的帧除非确有问题，不要再改。
- 正文修改要保存回计划，不能只存在于对话里；修改仍须服从 planner 的画面决定与全局写作规范。

## 6. 选择、隐藏与推进

- 审核通过后立即用 `select_keyframe_candidate(source="generation", source_id=<generation_id>)` 选定，
  再推进依赖它的帧。先完成本轮全部审核和选择，再 `continue`。
- 确认不会被采用的候选用 `manage_generation(action="dismiss")` 隐藏，让导演台只留值得看的内容。隐藏不删除 Generation 和 Asset，
  图片留在资产中心，需要时可以用 `source="asset"` 选回。
  - 只隐藏有明确依据的：看得清的结构缺陷、身份或造型错误、违背镜头设计，或计划修改后已过时。只是不如另一张的可用候选，以及你不够确定的，都不隐藏。
  - 某帧用完重试预算仍没有合格候选时，留下最接近的一条，让人看到问题。
  - 汇报时逐条列出隐藏了什么、为什么：隐藏是为了省人的时间，不是让结果显得比实际好。
  - 未隐藏的成功候选会让该 Segment 成为规划锁定节点；要用 planner 重新规划，先隐藏它们。
- 回头改选已被下游参考或复用的上游帧时，下游已生成的候选只会带 `inputs_outdated` 软提示，不会自动重做。
  改选前列出受影响的下游帧，询问用户是否一并重生成；不要悄悄只改上游。
- 范围内有 Segment“其他图片”规划时，与关键帧一样按依赖生成、审核和选择（`select_reference_image`），一致性要求见 planner。

## 7. 停止条件与汇报

遇到以下情况时停止推进，把已完成部分与具体问题交给用户：

- 某帧用完重试预算；
- 需要用户做创作决定（换构图、改镜头设计、接受某个瑕疵）；
- 依赖缺失且不在授权范围内（例如角色造型没有造型图、被参考的地点图片未选定）；
- 无法看图。

结束或停止时简短汇报：每帧最终选了哪条候选、复用了哪张图、各重试了几次及原因、隐藏了哪些候选及原因、仍存在的已知瑕疵、
未能核验的部分。长任务结束、失败或需要用户决定时，在结束本轮回复前调用 `ring_alarm` 叫用户回来。
