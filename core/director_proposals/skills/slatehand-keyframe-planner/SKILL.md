# Segment 关键帧规划

## 每张帧先答三问（必做）

整片规划、局部重做、改单帧提示词或换图前都要答。答案决定这张图要不要生成、放在哪、画什么。

**一、这段视频要演什么？** 把本 Segment 要演的动作拆成动词序列（例如“冲上前 → 握住把手 → 下压 → 拉开门”，上一段已演完的不算），分出三种状态：

- **启动前**：第一个动词还没发生。
- **进行中**：第一个动词已开始，最后一个还没完成。手已碰到把手、门已在动、人已起身都算。
- **已结束**：最后一个动词已完成，画面稳定。

**二、和上一段连续吗？** 满足任一条就是连续：工作集 Segment 的 `continues_from_previous=true`（同一 Shot 拆段）；上一段结束时动作还没完；用户或脚本写了连续、一镜到底；机位不变接着演。

连续时首帧不独立生图，按顺序取来源：

1. **共享边界**：上一段已启用尾帧且它就是交接画面时，计划里设 `continues_from_previous=true`，两段共用一张图。
2. **抽帧**：否则设 `start_extraction_suggested=true`，等上一段视频选定后抽它的真实画面。真实帧的人物、光线和道具一定接得上，新生成的图做不到。
3. **复用**：不便抽帧且画面和人物状态都没变时，复用同一镜头的已选图。

都不满足，或用户、脚本明确在这里换机位，才是切镜，才独立生成；人物状态、道具和光线仍接上一段结束时。连续的戏不能改成切镜来省事，“跳切更有冲击力”不是理由。

**三、这张图放哪个位置？**

| 位置 | 只能画 | 怎么判断 |
| --- | --- | --- |
| 首帧 | 启动前 | 看不到本段要演的任何东西：要入画的人没入画，要开的灯没开，要握的把手手还没碰 |
| 中间 | 进行中 | Core 没有中间槽位。必须锁定时放进 Ref2VA 的“其他图片”，在视频提示词里写明它何时出现；当前 recipe 没有这个槽位就先问用户。不必锁定就交给视频演 |
| 尾帧 | 已结束 | 最后一个动词已经完成，不是还在途中 |

状态和位置对不上就是计划错误。想到的画面是进行中时，往前退到启动前做首帧，往后推到已结束做尾帧，或改用其他图片，不要换个说法放进首尾槽位。只有用户或脚本明确要求切入动作中途才例外，并写明来源。

**把答案写出来**：规划提交后和单帧修改时，在回复里每帧一行，例如：

`场景 3－片段 4 首帧｜动作：冲上前 → 握把手 → 拉开门｜连续：是，同一 Shot｜来源：抽上一段视频｜画：启动前，手还护在胸前`

## 定位与上游

关键帧不是剧情插图，也不是“电影感”修饰词的集合，而是某一精确时间点的、可直接进入生产的摄影画面。
本 Skill 负责把已经批准的镜头设计落实为空间明确、叙事重点清楚的静态边界。它不能暗中改写
Scene、Shot、Segment、对白、旁白、动作结果或时长；若上游镜头设计不足，只能在既定意图内具体化。

结构化导演脚本是镜头功能、第一视觉重心、人物调度、连续性锚点、揭示路径和起止状态的上游权威，这些不能在本阶段改变；
信息缺失或互相冲突时，报告脚本需要回改，不用关键帧正文悄悄补写导演决定。

`composition` 里的景别和机位是实现这些意图的手段，写于还没有画面的时候，不一定成立。按 `cinematic-keyframe-design.md` 第 1 节检查后
确实不能服务镜头功能的，不要照搬：保持镜头功能、第一视觉重心和揭示路径不变，调整到能成立，在回复里写明调整了哪个 Shot、为什么。
计划提交后用 `edit_script` 的 `update_shot_fields` 写回该 Shot，让脚本、关键帧和视频提示词读到同一个镜头。这是本阶段的必要联动，不需另行授权；
规划请求未提交时不要写脚本，会让冻结的工作集过期。需要改动作、揭示顺序、切分或镜头功能，导演方案用文字写明了这个景别，
或覆盖该 Shot 的 Segment 已选视频（写回会清除选择）时，先问用户。

复杂调度、跨镜连续、揭示信息或 `9:16` / `2:1` 构图时，以及判断景别和重心时，必须阅读
[`references/cinematic-keyframe-design.md`](references/cinematic-keyframe-design.md)；
撰写每张帧的画面正文前，必须阅读
[`references/cinematic-frame-prompting.md`](references/cinematic-frame-prompting.md)。
必须遵守全局 `slatehand-image-prompt-writing`（契约 `global/` 资源或工作集 `image_prompt.global_skills`）：
有输入图时把“逐图标签与用途 + 正文显式引用”完整写进提示词，不写文件名；没有输入图时只写画面正文。
工作集 `image_prompt` 给出当前生图/改图插件的输入图指代约定；其 `plugin_skills` 目录非空时，正文写法还必须遵守
随插件发布的专业 Skill（全文在本契约的 `plugin/` 资源中），它只改变正文的组织方式，不改变本 Skill 的画面决定。
本 Skill 只负责规划。用户要求连续生成多个 Segment 的关键帧时，生成顺序、看图审核、重试、选图与复用按本契约的
`production/slatehand-keyframe-sequence/SKILL.md` 执行。

## 设计顺序

先读完整 Scene 作为上下文，答完开头三问后按以下顺序细化，proposal 只提交 schema。读取完整 Scene 不扩大本轮允许修改的 Segment 范围；
`planning_enabled=false` / `context_segment_ids` 只供阅读，输出的 `segments` 必须严格按 `writable_segment_ids`
顺序且只包含这些授权 Segment。需要新建、解除或改写与上下文 Segment 的共享边界时，应报告必须扩大的最小相邻 Segment，不能替上下文 Segment 编造提案。
`saved_keyframe_plan` 是当前 scope 内已经持久化的计划事实：共享 Keyframe 按 ID 去重，`bindings`
列出它在多个 Segment 的实际首尾用途，不能把 `owner_segment_id` 误解为唯一使用者。它不依赖图片生成就绪，实际可提交的图片映射以可执行输入为准。

1. **连续关系**：先区分切镜与真正一镜到底，将相邻 Segment（无论是否共享边界 Shot）作为一个完整摄影过程理解，确定每个分段的交接时刻。不能先独立设计各 Segment 的代表构图，再拼接不相容的首尾帧。
2. **整段变化**：沿已批准的动作与摄影机运动，梳理起点、经过和终点；检查哪些人物、环境、道具或身份特征会被新揭示。运动用于内部推演，不写进静态画面正文。
3. **实际输入**：先读 `video_inputs`：当前 recipe、合法 `frame_strategies`、槽位声明、已绑定的 `reference_inputs` 与已有 `reference_image_plans`。视频只看到显式绑定的素材；角色卡、地点资料和生图辅助图不会自动进入视频。把身份、空间和道具参考与精确起止画面的时间约束分别判断。
4. **边界状态**：把连续过程落实为具体首尾时刻；共享交接只能设计一次。若脚本要求交接瞬间跳到不同机位，又要求一镜到底，不能暗改动作或假装共享解决了冲突，应交由 Director 澄清或显式回改脚本。
5. **帧数选择**：先问这一段最不能出错的是哪个时刻，再按“首尾槽位与最少约束”选择；不把普通动作结果、表情变化或人物进出自动当作双帧理由。

随后对每张必要的静态边界细化：先定观众此刻必须先看见什么（唯一第一视觉重心），再定人物与物体的站位、朝向、视线、重心和遮挡，最后放摄影机；
景别不能服务镜头功能时按“定位与上游”调整并写回，不悄悄换镜头。检查动作方向、视线、轴线、道具和光线能否与前后帧剪接；选姿态稳定、轮廓清楚、手部和遮挡可控的静止瞬间。

## 画面描述必须具体

每个首帧和尾帧应按画面需要写清：

- 权威画幅、景别与摄影机观察位置；
- 左、中、右及前景、中景、背景的空间分配；
- 每个可见角色的位置、朝向、视线、身体重心、手部或接触关系；
- 关键道具的位置、状态与归属；
- 画框内可见的环境，以及其中需要变化或新出现的部分；结合 Scene setting、地点语义、状态和地点图片说明判断它们的样子，画框外的陈设不写。只有显式参考的地点图片才会作为生图输入；
- 光源方向、明暗关系，以及观众首先应注意的对象；
- 本帧的情绪：落实为面部、肢体、人物关系与光线的可见状态，强度服从脚本这一拍（见 `cinematic-frame-prompting.md` 第 4 节）；
- 若是首帧，画启动前的样子，并给后续动作留出空间；若是尾帧，明确动作结果和下一剪辑点。

禁止用“电影感、高质量、氛围感、构图优美、史诗感”等抽象词代替这些可见事实。不得写动作过程、
镜头运动过程、视频提示词、帧率、模型名或 Provider 参数。

## 画幅不是裁切参数

- 每种画幅都原生设计，不先按另一种画幅构图再裁切（写法见 `cinematic-keyframe-design.md` 第 6 节）；必须保持清晰轮廓、可读视线和足够的动作空间。
- `start_prompt_text` 和 `end_prompt_text` 保存全局 Skill 要求的完整提示词，有输入图时包含逐图用途与正文；不写 `9:16`、`16:9`、`2:1`、竖幅、横幅或宽银幕标签；
  画幅由 Core 在实际提交时固定编译，不能形成两个来源。

## 首尾槽位与最少约束

- Core 为每个 Segment 保留首尾两个时间语义槽位，但不要求两张都生成。
- `start`：只锁定起点。没有必须精确的落点时的默认选择，例如固定机位、小动作、普通表情变化、推近已知主体；动作过程交给视频模型。
- `end`：只锁定落点。这一段的戏落在动作结果上（亮起的屏幕和上面的文字、完成转头后定格的神情、门合上后的状态），或需要与下一段交接时使用；起点由视频生成。
  不要为了“有首帧”把结果提前画进首帧：观众一开场就看到了答案，动作也没有地方可走。
- `both`：起点、终点各有独立且必要的时间约束，或连续组必须承接两个共享边界时使用。逐端指出新增约束，不能用“更稳妥”“保证一致”代替判断。
  双帧不是更保险的选择：视频模型要在两张图之间补间，发丝、皮肤纹理、衣褶、陈设或光影的细微不一致都会在中段变成融化或形变。单帧能成立时不用双帧。
- `none`：当前 `video_inputs[].frame_strategies` 允许时，可只用显式独立图片、音频或视频参考，不锁定首尾时刻。缺少必要参考时说明需要规划/添加的素材，不能声称已经提交；Core 会在视频生成前校验媒体输入。
- 局部拉远揭示人物、房间或道具时，先判断独立参考是否已交代这些信息；只有确实需要锁定局部起点和揭示后的结束画面才使用双帧。首尾图必须对应真实起止时刻。
- 每个 Segment 输出 `frame_strategy=none|start|end|both`；只给启用且不继承的端点填写正文和角色，未启用端点可用空字符串与空数组，不需要为了通过 schema 编造另一张画面。Core 保留未启用端点已有计划。
- 首帧对应第一个覆盖 Shot 的开头，尾帧对应最后一个覆盖 Shot 的结尾。段内切镜主要由视频提示词表达，不为所有 Shot 强制画边界帧。
- `continues_from_previous=true` 表示显式共用同一交接图，首帧字段为空；真正共享边界仍要求前段尾帧、后段首帧启用。不要为了减少图片破坏已经明确的共享交接。
- `reference_images` 是可选增补数组，最多 4 项：`slot_index`（0–3）、`prompt_text`、`description`、`visible_character_ids`、`character_references`、`reference_asset_ids`。只规划当前 recipe 支持的其他图片槽位，沿用已有槽位，不重复规划已选图片或已有成功候选；未列出的规划保留。
- 其他图片与首尾帧一起进入视频，同一 Segment 内必须是同一套角色造型、同一空间状态与光线，否则视频模型会在两者之间摇摆；
  已选关键帧本身也可以作为其他图片（`select_reference_image` 的 `source="keyframe"`），但不能重复当前已启用的首尾帧。
- 其他图片没有视频时间位置，可以是任意画面内容。按缺失信息选择最少必要图片，不能因为有四张卡片就填满四张。`description` 说明预期参考用途，生成后人类按真实画面确认；规划不生成、不选择、不改已有视频输入绑定。

## 相邻 Segment 的连续边界

`continues_from_previous=true` 表示两边复用**同一张像素级关键帧**，不仅是剧情连续。只有摄影机位置、
景别、构图、人物姿态、道具和光线状态在交接的同一时刻完全相同时才能设置。相邻 Segment 共享边界 Shot
时通常应延续；普通正反打、切镜或明确换机位使用 `false`。一镜到底中的推近、绕行、拉远或景别变化发生在
Segment 内，不是切镜理由：必须先设计交接时刻，再从该时刻继续运动，不能比较两个 Segment 的代表构图后拒绝共享。
Director 本轮采用的连续长镜头方案即使记录在 `director_hypotheses`，也应落实为真实共享边界；
`required_shared_boundaries` 是最低强制集合，空数组不表示禁止或不需要共享。

设置为 `true` 时，当前 Segment 的 `start_*` 字段必须为空：`start_prompt_text=""`、
`start_visible_character_ids=[]`、`start_character_references=[]`、`start_reference_keyframe_ids=[]`；Core 沿用上一 Segment 的 `end_*`。
每个 Scene 的第一个 Segment 必须为 `false`。

相邻 Segment 不共享边界 Shot（明确切镜）时，`continues_from_previous=false`，两个边界默认是独立 Keyframe：
后段必须给出自己的 `start_*` 描述。也可显式共享为同一个 Keyframe，但像素级连续性要求不变。

当 Core 提供 `required_shared_boundaries` 时，表示 Director 已把本轮采用的连续镜头方案解析成必须共用的
时间边界，列出的是相邻 Segment 对。对应后一 Segment 必须设置 `continues_from_previous=true`；即使它随后
改变机位或景别，变化也只能发生在这个共用首帧之后。不得把该硬约束降级为仅保持人物、道具、光线或轴线状态相似。

共享同一图片只约束交接画面，不保证运动自动无缝；还要沿原脚本核对动作阶段、运动方向和摄影机运动的衔接。

### 同一 Shot 拆段：延续段不重新设计

工作集 `scenes[].segments[]` 的 `continues_from_previous=true` 表示该 Segment 与上一段覆盖同一个边界 Shot，
`boundary_reason` 是脚本记录的拆段原因。`model_constraint` 表示只因模型时长或对白条数上限把同一个镜头切成几段：
机位、景别、构图、空间与光线都不变，人物的表情、视线、手势和小幅走位是视频要演的过程，不是后段首帧需要
重新设计的理由。不要按后段的对白语气为它的首帧另编一个表演瞬间，
否则同一个镜头会在拼接处换成另一张独立生成的画面，背景、陈设和光线随之漂移。也不能借后段首帧改写
已批准的景别或机位（例如把固定双人中景改成单人反打近景）。

后段首帧的来源按开头第二问的顺序取，抽帧规则见下一小节。另外两种来源：

- **建议复用**：不便抽帧、或用户想先用静帧排完整段时，把 `start_reuse_keyframe_id` 设为同一 Shot 中最近一张
  已规划的帧（通常是上一段首帧），来源可以尚未选图；正文写成与来源相同的画面。批量生成跳过本帧并等待来源选定，
  之后用 `select_keyframe_candidate(source="keyframe")` 选入同一张图。
- **参考来源重新生成**：只有脚本在这个边界明确写了大位移、换机位或景别变化，才独立设计首帧；来源已选图时写进
  `start_reference_keyframe_ids`，正文写清保留什么、改变什么。

尾帧同理：同一镜头内的尾帧与本段首帧或同 Shot 其它帧画面相同时，用 `end_reuse_keyframe_id` 指向来源。
同一帧的抽帧与复用只能二选一。已有计划要补设或取消复用建议时，用 `edit_keyframes` 的
`update_frame_fields.fields.reuse_keyframe_id`（`null` 取消），不必重新规划。

#### 建议抽帧

共享关键帧只是计划中的交接画面，视频实际最后一帧只有在上一段启用尾帧时才被锁住。相邻 Segment 连续（共享边界 Shot，或动作跨段未完）、
但上一段不启用尾帧（例如对白段只用首帧或不用图片）时，下一段首帧若独立生图，手势、视线、光线与道具很容易在拼接处跳变。此时仍按交接时刻写 `start_prompt_text` 作为审核依据，并设置
`start_extraction_suggested=true`：关键帧卡显示“建议抽帧”，批量生成跳过这一帧。在回复里说明
这一帧等上一段视频选定后抽帧（人类用首帧卡“从上一 seg 抽取”，Agent 用 `generate_media(kind="frame_extraction")`）。这只是建议，用户要求直接生成时照常生成。已有计划要补标或取消标记时，用
`edit_keyframes` 的 `update_frame_fields.fields.extraction_suggested`，不必重新规划。

## 实际视频输入边界

其他图片的规划、读取、生成与选图流程见项目提示（`save_reference_image_plan`、`video_inputs`、
`generate_media(kind="reference_image")`、`select_reference_image`）；只有用户明确要求时才生成，选入卡片后才进入视频输入。
从资产库直接绑定的图片可能没有生图计划，仍要按 `reference_inputs` 读取，不能因没有 `reference_image_plans` 就忽略它。

实际视频输入以 `video_inputs[].slots`、`require_any` 和 `reference_inputs` 为准。首尾槽位只提交已启用且已选择的图；独立图片、音频和视频参考按当前 recipe 显式绑定。
FL2VA 至少需要一个边界帧；Ref2VA 可以没有首尾帧，但必须有至少一项媒体输入。规划阶段不能自动切换 recipe。
用于生图的角色造型、地点图片和辅助图只影响生图，不自动成为视频输入；独立参考不承诺精确的起止构图。
规划阶段只能判断描述中的覆盖，不能声称已审看尚未生成的图。生成后实际画面若遗漏必要主体或空间，
必须先审核/修正该图，不能继续把计划文字当作图片内容保证。

## 可见角色与参考约束

- 每张帧只列该静态时刻真正可见的角色 ID；未出现的角色不得为了“保持一致”而加入。
- Segment 的可见角色是覆盖 Shot 的并集；段内切换后仍可见的角色都可出现在首/尾帧。
- 共享边界时允许使用两侧 Segment 的角色并集，即使该角色在另一侧随后离开。
- 空镜返回空数组。
- 每张帧用 `start_character_references` / `end_character_references` 为可见角色选择本帧使用的造型：
  `[{character_id, look_id}]`，`look_id` 只能取自工作集 `visible_characters[].looks[].look_id`；`look_id: null`
  表示本帧不提交该角色的图。造型对应不同时期、服装或身体状态，按 `usage`（使用场合）与本帧所处剧情时刻选匹配的那一套。
- 角色只有一套造型时可以不列出该角色，Core 默认使用它；有多套造型时必须列出并选择，否则 Core 拒绝生成该帧。
  工作集同时给出造型的 `selected_asset_id` 与派生状态 `has_image`；需要核对角色外观时，用
  `read_media_input(asset_id=selected_asset_id)` 读取已选造型图。`selected_asset_id` 为 null（即 `has_image` 为 false）时
  该帧无法生成，提醒用户先为该造型设置造型图。
- Core 只提交所选造型的造型图，并在 `reference_mapping` 中标明角色与造型名；未列入可见角色的角色不得提交。
  角色造型图、前置帧与辅助参考合计最多 5 张输入图，多角色同框时尤其要精简选择。
- 用户在关键帧计划弹窗中选择的项目图片属于额外辅助参考，不替代角色卡身份参考。

## 参考其它已选关键帧

- 工作集 `referenceable_keyframes` 是全项目**已有选中图**的 Keyframe 索引（ID、所在 Scene/Segment/槽位、可见角色）。
  只有这些帧可被参考；只有候选、尚未选定的帧不能参考，因为最终选哪张未定。确实要参考某帧时，用
  `read_details(kind="keyframe", ids=[...])` 读取它的画面正文，不必为每个候选都读。
- 可选字段 `start_reference_keyframe_ids` / `end_reference_keyframe_ids`（各 0–4 个，不含本帧）让本帧生图时附带
  这些帧的**当前**选中图，作为“参考关键帧”输入，排在前置帧之后、辅助图之前。
- 用于跨 Segment 保持同一空间、人物状态、道具或光线：例如回到同一机位、同一房间的另一角度、换场后人物服装与伤痕延续。
  先用 `read_media_input` 审看被参考帧的实际图片，再在正文里写清该参考图要保留什么、改变什么；不要把参考当成复刻。
- 下游帧可在上游选定后用 `edit_keyframes` 的 `update_frame_fields.fields.reference_keyframe_ids` 写入，与本 proposal 是同一字段。
- 回切到画面与人物状态都没有变化的同一机位（例如多轮对话中重复出现的同一特写）时，后一帧不必重新设计：
  正文写成与被复用帧相同的画面，并设置 `start_reuse_keyframe_id` / `end_reuse_keyframe_id` 指向它（来源可尚未选图）。
  什么时候改为重新生成见 `slatehand-keyframe-sequence` 第 3 节。
- 被参考帧之后被改选时，下游已生成候选只带 `inputs_outdated` 软提示；被参考帧撤销选择时，下游帧在其重新选定前不能生成，批次会把它列为等待项。

## 地点语义与图片

Scene 可以绑定一个语义地点与状态；Shot 和 Keyframe 都不绑定地点。工作集 `location_library` 给出当前 Scene 使用的地点、
固定陈设、主光、状态和图片强制说明，`location_images` 是全项目地点图片索引，`referenceable=true` 表示可被本帧参考。
要参考其它地点的图片时，先用 `read_details(kind="location_image", ids=[...])` 读取它的强制说明。
Planner 应把这些事实与 Scene setting、Shot 构图和动作一起用于写出自洽空间，不能假设地点图片的机位会被复刻。
地点是这一帧的背景事实，不是这一帧要展示的内容：不因地点里有门窗和家具就把它们放进画框，也不为保持地点一致而拉远。

- 地点图片默认只是资料。需要它的实际画面约束空间时，在 `start_reference_location_image_ids` /
  `end_reference_location_image_ids` 里列出其 `image_id`（各 0–4 个，只限 `referenceable=true` 的普通图片条目）；
  Core 以“地点参考”角色提交其当前选中图并附带图片说明。全景图不能直接参考，需要时请用户先取景为普通子图。
- 先用 `read_media_input` 审看图片并核对说明，在正文里写清这张图提供哪些空间、陈设或光线事实，以及本帧机位与它的差异；继承什么由本帧画框决定（见 `cinematic-frame-prompting.md` 第 1 节）。
- 只在本帧确实需要从它取得光线、材质或空间事实时才参考地点图片，和角色造型图、前置帧、参考关键帧共享 5 张名额。
- 没有地点图片、图片未选候选或没有合适视角时，仍应根据地点文字和镜头上下文完成画面设计，不把它报告为生成依赖缺口。
- 图片的强制 `description` 是理解实际画面的依据；`prompt_text` 只是历史生成意图，不能当成图片已实现的事实。
- Planner proposal 不新增或替换 Segment 辅助图；地点图片用上面的参考字段，`edit_keyframes` 的
  `update_frame_fields.fields.reference_location_image_ids` 写同一字段。

## 输出前自检

- 每帧三问的答案写进回复了吗？
- 不读剧情文字，单看画面描述，能否知道观众先看哪里？
- 这一帧的景别能说出戏剧理由吗？有没有为交代地点而拉远，或要求相距很远的人和物同时清晰？调整过的 Shot 是否已说明并安排写回？
- 人物、道具和环境是否有明确二维位置与三维关系？
- 姿态是否是可生成的静止瞬间，而非一串动作？
- 首帧是启动前吗？有没有出现这一段才要演的动作或结果（手已碰到道具、人已入画、灯已开）？尾帧的最后一个动作完成了吗？
- 前后帧的屏幕方向、视线、道具、光线是否无意外跳变？
- 是否错误地把普通连续剪辑标成同一张共享帧？
- 一镜到底后段是否启用首帧？同一 Shot 拆段的后段首帧是否按“共享 → 抽帧 → 复用 → 参考重生成”选了来源，
  而不是为对白语气另编一个表演瞬间并独立生图？
- 身份、场景和道具信息分别由哪些实际视频输入提供？是否把生图辅助图误当成视频输入？
- 尾帧是否有独立必要的时间约束？能用单首帧或 none 吗？
- 是否根据 Scene 地点与状态写出了自洽空间？参考的地点图片是否已审看、确有必要，且没有把未参考的图片误称为输入？

真正生成时，必须由用户明确要求；本 Skill 不生成图片。


## 正文约束复核

用户明确指定的提示词语言优先于示例或旧正文。提交前逐项核对明确排除项，例如无字幕、无水印、
无新增角色：必须在最终静态画面正文中表达，不能只留在分析或工作集，也不能以“场景不变”代替。
未要求的排除项不自动新增。正文仍只描述静态可见状态；这不授权静默改写已保存提示词。
